# web/ — League Remote phone PWA

Vue 3 + Vite + TypeScript. It must look, move and behave like a native iOS 26/27 (Liquid Glass) app on iPhone.
The rules below are the design system. Never replace the app's own mark (`components/AppMark.vue`,
`public/favicon.svg`).

## Commands

```bash
npm run dev -- --port 5179 --strictPort   # dev server; review screens with /?demo=<scenario> (below)
npm run tokens                            # regenerate src/styles/tokens.{css,ts} after editing design/tokens.json
npm run build                             # tokens + vue-tsc type-check + vite build — must pass before you commit
```

`npm run dev` proxies `/hub` and `/client-sounds` to the connector on `localhost:5080` (`LR_DEV_CONNECTOR` points the
proxy elsewhere, for example `http://127.0.0.1:9` to stay away from a running connector).
A `?demo=` page never opens the hub connection (`hub.ts` checks `isDemo` from `lib/demoMode.ts`: no socket, no
sign-in, pairing answers "No PC in a demo"). Only pages without `?demo=` connect.

## Rules

**Tokens, never literals.** In CSS use `var(--token)`; in script import `SIZE`, `SPACE`, `DURATION`, `SPRING`,
`cssSize()`, `scaled()` from `src/styles/tokens.ts`. A value the tokens don't have gets a token in
`design/tokens.json` (with a `usage` note), then `npm run tokens`. Allowed literals: `0`, percentages, `1fr`,
`100dvh`, and the px stroke constants in `components/base.css` (`--lr-hairline`, `--lr-stroke`, rings).
Named constants are fine for behaviour that isn't visual (a scan interval, a hysteresis in px).

**Screens compose components; they don't style.** No `<style>` in `src/screens/*.vue`. A pattern used twice is a
component. A screen part with its own layout gets its own component (scoped `<style>`, tokens only), like
`pair/PairingForm.vue`. Utility classes allowed in markup: type styles (`.body`, `.headline`, …), `.lr-secondary`,
`.lr-accent-text`, `.lr-sr` (screen-reader only), `.lr-inline-symbol`, `.lr-icon`.

**Dynamic Type.** The root font is the user's text size (`font: -apple-system-body`, 17px by default). Type styles
grow up to their AX5 size (`maxFontSize`), spacing up to 1.25×, sizes up to 1.5×; bar chrome (`"dynamic": false`:
tab bar) doesn't grow. So: size text only with type-style classes, size layout only with tokens, use `min-height`
(not `height`) on anything holding text, and let titles wrap rather than truncate. Inputs: `max(16px,
var(--font-size-…))` or iOS zooms into the field.

**Colour.** Follow the semantic tokens: `bg` / `bg-elevated` / `bg-tertiary` (wells inside elevated surfaces);
`label` / `label-secondary` / `label-tertiary` (placeholders, disabled only). Gold (`accent`) = your action, text on
it is `on-accent`; red = ban / enemy / destructive / error; green = accept / online; orange = waiting. Coloured text
uses the `-text` tokens. Never tell states apart by hue alone. Dark, light and both Increase Contrast themes come from
the tokens — check any new pairing in all four.

**Materials.** Glass (`.lr-glass`, `.lr-glass-thick`) only on floating controls: nav buttons, action bar, tab bar,
banners, menus, partial sheets. Content (lists, cards, tips) is opaque `bg-elevated`. Never glass on glass: floating
chrome hides while a modal sheet is up (`sheetStack.modal`). `.lr-glass-clear` / `LrButton variant="clear"` only over
the camera, always over `dim-clear`. Glass reads `--lr-glass-fill` / `--lr-glass-fill-thick` (`glass.css`), never the
colour tokens directly: they follow the glass amount, Reduce Transparency and Increase Contrast. Blur values are
`material` tokens, composed into `--lr-glass-blur*` in `base.css`.


**Liquid Glass rules.** Apple's rules and the reasons behind them are in `design/liquid-glass/` (start at
`reference/01-material.md`; `reference/03-web-implementation.md` has the recipes). Apple publishes no blur, opacity or
radius numbers except the 35% under clear glass: every value here is tuned by eye, so never present one as Apple's, and
take any new metric from Apple's UI Kit.

- Tiers: opaque (`glass-tinted`, no blur: Reduce Transparency, Increase Contrast), frosted (the real look on iPhone),
  refractive (`useRefraction`: Chromium only, tab bar and action bar capsule only). Nothing may depend on the third.
- `--lr-glass-amount` (`lib/glassAmount.ts`, per phone, no Settings row): 0 ultraclear, 0.5 default, 1 tinted. A page
  can't read iOS 27's slider or, in Safari, Reduce Transparency. Without a stored amount no `color-mix()` runs.
- Text on glass: `label`, and `label-secondary` resolves to `label-secondary-glass` inside every glass surface.
- At most four glass surfaces on screen. Several icon buttons side by side share one `.lr-glass-group` capsule; never
  text and icons in one group.
- Only knobs turn to glass inside content, only while held (switch, slider, segmented thumb).

Review every glass change against this list, at `?demo=materials&glass=0` (worst-case backdrop) and with
`node scripts/check-glass-contrast.mjs` (from `web/`):

- No `.lr-glass*` inside another `.lr-glass*` (except knobs while held).
- No `opacity`, `filter`, `mask` or `will-change` on any ancestor of glass: it would blur only that ancestor's content.
- Clear glass only inside the scanner, always over `dim-clear`.
- Text on glass at 4.5:1 over the worst-case backdrop at glass amount 0.
- Every new animation has a `prefers-reduced-motion` branch.

**Connection states.** A screen that shows the PC's data starts with `<ConnectionEmptyState />` and puts its own
content (loading, empty, lists) under `v-if="!connectionEmpty"` (`connection.ts`): offline, connecting, reconnecting,
signing in and not paired read the same on every tab, never as "No Conversations" or a spinner that never ends.
Settings' first section has two rows: PC (`pcStatus`, this phone's link to the PC) and League (`clientStatus`).

**Champion Select status.** The draft's stage and timer are in one place, always on screen: the action bar's
status while the picker is down, the picker's `TurnHeader` while it is up — both name the turn being played ("Enemy
Picks", "Declare Intent", "Your Pick") with the acting side's dot (`DRAFT_DOT` in `src/draft.ts`); when yours
comes is the bar's detail line. Lock In / Ban shows only on your own turn (not during Declare Intent or the turns before
yours).

**Draft board.** Champion Select fits one screen (`champselect/DraftBoard.vue`): both teams face each other with their
bans above them, portraits on the screen's outer edges, your team's spells stacked beside them, names towards the
middle. No line, strip or number for the order: an empty slot is an empty tile and the acting player's rings. A hover is
the translucent portrait and no word. The board keeps one compact size (`champ-row`) throughout the draft; what
doesn't fit under the board (the loadout behind the picker) scrolls. The title, More Options (Dodge) and chat
are in the nav bar; spells and rune page share one line (`SpellSlots tray`). Bench modes (ARAM) keep the team lists under a
large title: champions are dealt, so there is no draft to show.

**Layout.** One prominent (gold) action per screen, in the `ActionBar`. Inset-grouped lists carry everything
else. Touch targets ≥ 44pt (`--hit-min`; pad small visuals with an `::after` hit region). Safe areas via
`--safe-*`; screen edges via `--lr-inset-left/right`. Concentric corners: inner radius = outer radius − padding.

**Motion.** Respond on pointer-down (`installPressStates`, `:active`). CSS transitions pair a duration token with
its easing token (`var(--dur-snappy) var(--spring-snappy)`). Anything a finger drives (sheet, banner, edge swipe,
segmented thumb) uses `animateSpring` from `lib/spring.ts` with `SPRING.*`, starts from the live value and takes the
release velocity. `spring-bouncy` only after momentum (a flick, the lock-in pop) and when pressed glass lets go.
Pressed glass (`.lr-glass-interactive`: LrButton glass, clear, prominent; tabs) swells to `glass-press-scale` with a glow
from the touch point (`pressStates` writes `--lr-px` / `--lr-py` on that element); gray and plain buttons press down.
Menus, banners and the accessory materialize with the shared `lr-materialize-in` / `-out` keyframes on `spring-menu`
(scale, opacity, a small blur of their own pixels); never animate a backdrop blur. Things leave the way they came. Under
`prefers-reduced-motion` everything becomes a `dur-fade` cross-fade (handled in `styles/components/` and
`lib/spring.ts`); the spinner keeps turning. Countdowns step linearly (`dur-step`), never on a spring.

**Haptics and sound.** **Sounds and music are League's own assets**, read from the user's installation by the connector (`ClientSoundCatalog` → `/client-sounds/manifest.json`) — never a synth or a file of our own when the client has a sound for that moment; a synth only where the client has none (and say so in the catalog). Match the client's timing too (when a countdown starts ticking, which sound for pick vs ban). `tapFeedback()` (click + selection haptic, `haptics.ts`) in tap handlers of controls that send something;
`haptic('success'|'error'|…)` when the client confirms. iOS plays haptics only inside a user gesture — a bonus, never
the only signal. Sounds and music **keep playing in the background** (Settings › Sounds & Haptics › Play in Background, on by default)
until the app is closed: never pause or skip them because the page is hidden. On iOS that means plain `<audio>`
elements while hidden (Web Audio is interrupted there) plus a near-silent keep-alive loop while connected — see
`sound/platform.ts` and `sound/session.ts`; new sound paths must go through `play()` / `setMusic()` to get this. Banners: `toast(text, 'info' | 'success' | 'warning' | 'error')`.

**Voice.** Title Case for titles and buttons, sentence case for the rest; verbs first, name the object ("Lock In
Ahri"); `…` means in progress or more choices; no exclamation marks, no plumbing words (LCU, hub, cellId).

to a friend with `friendOf()` / `isFriend()` (`friends.ts`: by puuid, by name only without one), so a player reads the
same everywhere. A modal `Sheet` already closes by
✕, swipe and Escape: don't add a Cancel button to it. Missing a pattern (segmented control, swipe action…)? Build it
as an `lr-` component here, with a demo, before using it in a feature.

## Accessibility checklist (every change)

- Every control has a visible label or `aria-label` written as an action ("Mute Sounds", "Actions for Jungle");
  icon-only `LrButton`s require `ariaLabel`. Decorative symbols and art: `aria-hidden` / `decorative`.
- One `h1` per screen (`LargeTitle`); section headers are `h2` (`ListSection header`).
- Covers and modal sheets are modal layers (`useModalLayer` / `Sheet modal`): the rest of `<body>` goes inert
  (banners stay live), focus moves in (quietly: no ring until the keyboard is used, `[data-lr-quiet-focus]`) and
  comes back. A new full-screen cover must use `useModalLayer`.
- Live regions: status changes `role="status"`, errors `role="alert"` (BannerHost does this), timers silent
  (`TimerText`, `CountdownRing`) with announcements only at 10 and 5 s.
- Selected state is exposed (`aria-pressed`, `aria-current`, `aria-checked`), not only drawn.
- Works at the largest text size, in light, dark and Increase Contrast, at 375 and 430 px, with Reduce Motion.
- Pinch zoom is off on purpose (`index.html` viewport, `main.ts` gesture handlers), like a native app; text size comes
  from Dynamic Type instead. So every screen must work at the largest text size: that is the zoom.

## Adding a screen or a demo

1. Screen in `src/screens/` built from `lr-` components; root `<div class="lr-content">` starting with a `LargeTitle`.
2. Wire it in `App.vue` (`view` is picked by the game state; tabs by `nav.tab`) and its title in `navTitle`.
3. Add or extend a scenario in `src/dev/demo/` (the `switch (scenario)` in `index.ts` is the list, plus `offline` and `pair`; most scenarios take
   extra query parameters such as `&game=<n>` or `&text=40`, documented next to the case). Handle the screen's commands
   in the demo's command handler so it reacts like the real app.
4. Check it at 375 and 430 px, light and dark, and with `document.documentElement.style.fontSize = '40px'`
   (≈ the largest accessibility size); `npm run build` must pass.
